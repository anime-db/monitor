# Ловушки `anime-db/monitor`

Только нетривиальное: выглядит понятно, но ломается — или выглядит странно, но сделано намеренно. Тривиальное (видно из имени файла/класса за 5 секунд) сюда не попадает.

## Выглядит странно — но сделано НАМЕРЕННО (не «чинить»)

### Опечатки в именах методов — это реальные символы
`lunchProcesses()` (имелось в виду *launch*) и `clearCash()` (*cache*) — рабочие имена, на которые завязаны `SLOT(...)`-строки и вызовы. Слепое переименование «по орфографии» порвёт connect-ы. Переименовывать только синхронно во всех `.cpp`/`.h`/`SLOT()` или не трогать. Зафиксировано в `TrayIcon.{h,cpp}`.

### `QProcess`-члены с `this` в качестве QObject-родителя — НЕ двойное владение
В `TrayIcon` конструкторе: `routerProc(this), taskSchedulerProc(this)`, при том что это **value-члены** (не указатели). Выглядит как баг двойного удаления (родитель удалит + деструктор члена). На деле безопасно: дочерний `QObject` при разрушении сам снимается со списка детей родителя раньше, чем отработает деструктор `QObject`-базы. Не «исправлять» убиранием `this`.

### `MSettings::value()` ПИШЕТ в файл при чтении
При отсутствии ключа `value(key, default)` записывает `default` обратно в `config.ini` и возвращает его. То есть «просто чтение» настройки мутирует файл на диске. Это материализация дефолтов, поведение намеренное — не считать побочным эффектом-багом и не «оптимизировать» убиранием записи.

### Смена папки приложения чистит кэш Symfony
Если `appDirPath != lastAppPath`, конструктор `TrayIcon` вызывает `clearCash()` (`app/console cache:clear --env=prod`). Выглядит как агрессивное удаление, но необходимо: Symfony кэширует **абсолютные** пути, и после переезда папки приложение падает на устаревшем кэше.

### Проверка пути на «только ASCII» — защита, а не паранойя
`TrayIcon` отвергает запуск, если `appDirPath` содержит символы вне `[A-Za-z0-9.:/\[\]()_\-\\]` (пробелы, кириллица, спецсимволы) — критическая ошибка и выход. Причина: встроенный веб-сервер PHP не работает с такими путями. Не ослаблять регулярку «чтобы запускалось из Program Files».

## Выглядит понятно — но ЛОМАЕТСЯ

### `>nul 2>&1` в команде запуска НЕ перенаправляет вывод
`lunchProcesses()` собирает команду строкой с хвостом `>nul 2>&1` и зовёт `QProcess::start(const QString&)`. Этот перегруз **не запускает шелл** — Qt сам разбивает строку и вызывает `CreateProcess`. Поэтому `>nul` и `2>&1` уходят в `php` как обычные аргументы. Вывод НЕ подавляется. Для редиректа нужен либо `cmd /c "..."`, либо `start(program, QStringList)` + `setStandardOutputFile(QProcess::nullDevice())`. Детали — [../docs/BUGS.md#b2](../docs/BUGS.md#b2).

### `config.ini` живёт относительно CWD, а не папки exe
`MSettings : QSettings("config.ini", IniFormat, 0)` — относительный путь резолвится `QSettings` от **рабочего каталога процесса**, не от `applicationDirPath()`. При запуске из ярлыка с заданной «Рабочей папкой» настройки уедут в другое место. [../docs/BUGS.md#b3](../docs/BUGS.md#b3).

### Перевод включается по СТРАНЕ, а не по языку
`main.cpp` грузит `ru.qm` только если `QLocale().country() == QLocale::RussianFederation`. Русскоязычный пользователь в Казахстане/Беларуси получит английский UI. Не путать с проверкой языка. [../docs/BUGS.md#b4](../docs/BUGS.md#b4).

### `lunchProcesses()` не поднимет упавший процесс, если второй жив
Guard в начале: `if (routerProc.state() != NotRunning || taskSchedulerProc.state() != NotRunning) return;` — условие через `||`. Если один из двух процессов PHP упал, а второй работает, повторный Start ничего не перезапустит. [../docs/BUGS.md#b7](../docs/BUGS.md#b7).

### Exit не убивает дочерние процессы PHP
Пункт меню Exit подключён напрямую к `QCoreApplication::quit()`, минуя `stopSlot()`. Дочерние `php.exe` (веб-сервер и планировщик) НЕ останавливаются и остаются висеть после выхода из трея. Только `Stop`/`Restart` зовут `kill()`.

### `startSlot()` открывает браузер сразу, до готовности сервера
`startSlot()` = `lunchProcesses()` + немедленный `openUrl()`. PHP-сервер ещё не успел забиндить порт → первое открытие может упереться в connection refused. [../docs/BUGS.md#b5](../docs/BUGS.md#b5).

## Инфраструктурные

### `anime_monitor.pro` — единственный источник списка файлов
Нет автосканирования каталога. Новый `.cpp`/`.h` не попадёт в сборку, пока вручную не добавлен в `SOURCES`/`HEADERS`. Аналогично ресурсы — только через `icons.qrc` (`RESOURCES`).

### После правки `tr()`-строк нужен `lupdate` + `lrelease`
`ru.ts` хранит `<location filename=... line=...>`. Сдвиг строк в `TrayIcon.cpp` рассинхронит локации; рантайм грузит `ru.qm`, который надо перекомпилировать. Правка строки в коде без перекомпиляции перевода = разъехавшийся/потерянный перевод.

### `reason == 3` — это `QSystemTrayIcon::Trigger`
В `activatedSlot` магическое число `3` = левый клик (`Trigger`). Не очевидно без таблицы enum; при правках сравнивать с именованной константой.
