# Операционный контекст `anime-db/monitor`

Кто и как использует утилиту, модель угроз, легаси-решения и их статус. Конкретные баги — в [../docs/BUGS.md](../docs/BUGS.md); рекомендации — в [../docs/RECOMMENDATIONS.md](../docs/RECOMMENDATIONS.md).

## Кто вызывает

- **Единственный потребитель — конечный пользователь на Windows**, который двойным кликом запускает `anime_monitor.exe` (обычно из автозагрузки или ярлыка).
- **Нет внешних/удалённых вызывающих.** Это локальный десктоп-лаунчер, не сервис и не демон. API/RPC/сети, обращённой к самому monitor, нет.
- **Единственный экземпляр** гарантируется через `QSharedMemory("anime_monitor")`: вторая копия завершается с кодом 1.
- Дальше monitor сам становится «вызывающим» для двух процессов PHP (веб-сервер + планировщик) и для браузера (открывает URL).

## Среда исполнения

- **Только Windows** — осознанно. Весь стек завязан на Windows: пути с `\`, `*.exe`, попытка шелл-редиректа `>nul 2>&1`, портативный `bin\php\php.exe`.
- Рядом с exe ожидается раскладка дистрибутива Anime DB: `app/`, `web/`, `bin/php/`. Их отсутствие → процессы PHP не стартуют (молча, т.к. вывод не отслеживается).
- Qt 4 **или** Qt 5 (`greaterThan(QT_MAJOR_VERSION,4): QT += widgets`).

## Модель угроз

Контекст — локальный десктоп одного пользователя, не многопользовательский сервер. Тем не менее:

| Поверхность               | Риск                                                                                                                                                                                                                                        | Статус                                                  |
|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------|
| **Биндинг `0.0.0.0`**     | Дефолт `addr=0.0.0.0` поднимает dev-сервер PHP на ВСЕХ интерфейсах → коллекция и админка Symfony доступны всей локальной сети (Wi-Fi/LAN), а не только машине.                                                                              | 🔴 открыт, [../docs/BUGS.md#b1](../docs/BUGS.md#b1)     |
| **Встроенный сервер PHP** | `php -S` официально «не для продакшна»: однопоточный, без TLS, ограниченная защита. Приемлемо лишь при строго локальном `127.0.0.1`.                                                                                                        | 🟠 присуще, держать на localhost                        |
| **`config.ini` как вход** | Значения `addr`/`port`/`php` подставляются в строку команды, которую `QProcess::start(QString)` бьёт по пробелам → пробел/спецсимвол в файле = инъекция аргументов. Файл локальный, но может быть изменён другой программой/синхронизацией. | 🟡 латентно, [../docs/BUGS.md#b11](../docs/BUGS.md#b11) |
| **ASCII-валидация пути**  | Митигация, не угроза: блокирует запуск из путей, ломающих PHP-сервер.                                                                                                                                                                       | ✅ намеренная защита                                     |

Сетевого ввода в сам monitor нет — основной вектор именно экспозиция запускаемого им PHP-приложения наружу.

## Легаси-решения и их статус

| Решение                                                       | Происхождение / статус                                                                                                                                             |
|---------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Проект 2014 года, Qt Creator (`anime_monitor.pro.user` в VCS) | Историческое. `*.pro.user` стоит убрать из git + добавить `.gitignore` ([../docs/BUGS.md#b12](../docs/BUGS.md#b12)).                                               |
| Вырезанный `MLogger`                                          | Остались закомментированные `//#include "MLogger.h"` и `MLogger::info(...)`. Логирования сейчас нет; следы — кандидат на удаление или восстановление лёгкого лога. |
| `>nul 2>&1` как способ заглушить вывод                        | Не работает (нет шелла в `start(QString)`). Намерение было верным, реализация — нет. [../docs/BUGS.md#b2](../docs/BUGS.md#b2).                                     |
| Перевод по `country == RussianFederation`                     | Историческое упрощение; правильно — по языку. [../docs/BUGS.md#b4](../docs/BUGS.md#b4).                                                                            |
| «monitor» без мониторинга                                     | Имя осталось от замысла; авто-перезапуск/детект падений не реализованы. [../docs/BUGS.md#b6](../docs/BUGS.md#b6).                                                  |
| Опечатки `lunchProcesses`/`clearCash`                         | Зафиксированы как рабочие символы; трогать только синхронно. См. [gotchas.md](gotchas.md).                                                                         |
| Кроссплатформенность                                          | Сознательно НЕ поддерживается. Не считать пробелом — это решение, а не недоработка.                                                                                |

## Изменения через внешний репозиторий

Этот каталог в воркспейсе `anime-db-workspace` — клон внешнего репозитория `git@github.com:anime-db/monitor.git`. По правилам воркспейса в `docs/*/` напрямую не коммитят — правки уезжают через `push_docs.sh` (ветка `feature/update-cross-links`). При работе прямо в клоне monitor — обычный git-флоу. Ветки: `master`, `2.x`.
