# Рекомендации по `anime-db/monitor`

Сквозные улучшения кодовой базы: безопасность, поддерживаемость, гигиена. Конкретные дефекты с фиксами — в [BUGS.md](BUGS.md); контекст — в [TECHNICAL.md](TECHNICAL.md).

## Безопасность

### 1. Биндинг только на localhost по умолчанию
Самое важное изменение. См. [BUGS.md#b1](BUGS.md#b1). Дефолт `127.0.0.1` закрывает приложение от локальной сети. Доступ по сети должен быть осознанным выбором через `config.ini`, а не поведением «из коробки».

### 2. Не доверять значениям из `config.ini` при сборке команд
`config.ini` — это файл на диске, который может быть изменён (другой программой, пользователем, синхронизацией). Подстановка его значений в строку команды (`addr`, `port`, `php`) создаёт риск инъекции аргументов. Переход на `start(program, QStringList)` ([BUGS.md#b2](BUGS.md#b2), [B11](BUGS.md#b11)) устраняет проблему: экранирование берёт на себя Qt.

### 3. Учитывать ограничения встроенного сервера PHP
`php -S` официально помечен как «не для продакшна» (однопоточный, без TLS, ограниченная безопасность). Это приемлемо для строго локального десктоп-сценария, но стоит:
- зафиксировать это в документации для пользователя;
- держать биндинг на `127.0.0.1`;
- по возможности выбирать порт, не конфликтующий с типовыми сервисами.

### 4. Подавлять, но при необходимости логировать вывод
Сейчас попытка заглушить вывод (`>nul 2>&1`) не работает ([BUGS.md#b2](BUGS.md#b2)). Лучше осознанно перенаправлять stdout/stderr процессов в файл-лог (или `nullDevice()`), чтобы при разборе инцидентов была диагностика.

## Надёжность и наблюдаемость

### 5. Сделать «монитор» монитором
Подключить `QProcess::finished`/`errorOccurred`, показывать `showMessage()` в трее при падении, опционально — контролируемый авто-рестарт с backoff и лимитом попыток. См. [BUGS.md#b6](BUGS.md#b6), [B7](BUGS.md#b7).

### 6. Минимальное логирование
В `MSettings.cpp` остались следы вырезанного `MLogger`. Лёгкий лог в файл рядом с exe (старт/стоп/коды возврата процессов, путь к `config.ini`) резко упростит поддержку у пользователей без отладчика.

### 7. Корректное завершение дочерних процессов
Пункт меню Exit вызывает `quit()` напрямую, не останавливая `routerProc`/`taskSchedulerProc`. Стоит перед выходом гарантированно завершать процессы (`terminate()` → таймаут → `kill()`), чтобы не оставлять висящий `php.exe`.

## Поддерживаемость

### 8. Убрать магические числа
`reason == 3` → `reason == QSystemTrayIcon::Trigger`. Самодокументируемо и устойчиво к изменениям enum.

### 9. Решить судьбу опечаток в именах
`lunchProcesses` (launch), `clearCash` (cache) — рабочие, но цепляют глаз. Переименование безопасно (символы используются только внутри `TrayIcon`), но требует синхронной правки `.cpp`/`.h`/`SLOT(...)`-строк. Либо переименовать аккуратно, либо явно задокументировать как «так и задумано» (сейчас зафиксировано в [CLAUDE.md](../CLAUDE.md)).

### 10. Удалить мёртвый код
`isPathChanged()` ([BUGS.md#b9](BUGS.md#b9)) и закомментированные `MLogger`-строки.

### 11. Вынести «магию» путей в константы
Относительные пути `./web`, `./app/router.php`, `./app/console`, `./bin\php\php.exe`, имя команды `animedb:task-scheduler` разбросаны по коду строками. Собрать в именованные константы — меньше риска опечатки и проще менять раскладку дистрибутива.

## Гигиена репозитория

### 12. Добавить `.gitignore`
Пример для qmake/Qt Creator:
```gitignore
# Qt Creator
*.pro.user
*.pro.user.*

# Сборка
Makefile*
*.o
moc_*.cpp
qrc_*.cpp
ui_*.h
debug/
release/
*.exe
```

### 13. Убрать `anime_monitor.pro.user` из VCS
`git rm --cached anime_monitor.pro.user` — это локальное состояние IDE с путями конкретной машины. См. [BUGS.md#b12](BUGS.md#b12).

### 14. GPLv3-заголовки
Добавить шапку с копирайтом и ссылкой на лицензию в каждый `.cpp`/`.h` — требование проекта и FSF. См. [BUGS.md#b8](BUGS.md#b8).

### 15. Оптимизировать `favicon.ico`
158 КБ для иконки — много (она вшита и в `.qrc`, и в `.rc`). Пересобрать ICO с разумным набором размеров (16/32/48) уменьшит размер exe.

## Процесс и качество

### 16. Минимальный CI
Даже без юнит-тестов полезен workflow, который просто проверяет, что проект собирается (qmake + сборка под MinGW/MSVC) на каждый PR. Это ловит регрессии компиляции и битые `.pro`.

### 17. Документация для пользователя
Короткая инструкция: требования (PHP в `bin/php`, раскладка `app/`/`web/`), как сменить порт/адрес, ограничение «только ASCII-путь», что делать при ошибке кэша. Часть этого уже есть в [PROJECT.md](PROJECT.md)/[TECHNICAL.md](TECHNICAL.md) — стоит свести в пользовательский раздел.

## Чего НЕ нужно делать

- **Не добавлять кроссплатформенность** ради неё самой — проект сознательно Windows-only, и весь стек (раскладка PHP, редиректы, пути) завязан на Windows. Это осознанное решение, а не недоработка.
- **Не переусложнять** — это утилита на ~330 строк. Ценность в простоте; вводить тяжёлые абстракции (DI, плагины, конфиг-фреймворки) контрпродуктивно.
