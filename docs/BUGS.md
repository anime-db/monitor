## B1
🔴 **Веб-сервер по умолчанию слушает `0.0.0.0`** — `TrayIcon.cpp` (дефолт настройки `addr`).

`addr` по умолчанию `0.0.0.0`, и сервер запускается как `php -S 0.0.0.0:56780 ...`. Встроенный веб-сервер PHP **не предназначен для продакшна** (однопоточный, без защиты) и при таком биндинге доступен **всем хостам локальной сети**, а не только самой машине. Личная коллекция и админка Symfony оказываются открыты соседям по Wi-Fi/LAN.

**Исправление.** Сменить дефолт на `127.0.0.1`:
```cpp
addr = MSettings::value("addr", "127.0.0.1").toString();
```
Кто осознанно хочет доступ по сети — поменяет значение в `config.ini` сам.

## B2
🟠 **`>nul 2>&1` не работает как редирект** — `TrayIcon.cpp`, `lunchProcesses()`.

Команда собирается строкой и запускается через `QProcess::start(const QString&)`, который **не использует шелл**: Qt сам разбивает строку и вызывает `CreateProcess`. Поэтому `>nul` и `2>&1` передаются `php` как обычные аргументы, а не перенаправляют вывод. Вывод сервера не подавляется; PHP может выдать ошибку из-за лишних аргументов.

**Исправление (вариант А — без шелла, предпочтительно):**
```cpp
QStringList args;
args << "-S" << (addr + ":" + port)
     << "-t" << QDir::cleanPath(appDirPath + "./web")
     << QDir::cleanPath(appDirPath + "./app/router.php");
routerProc.setStandardOutputFile(QProcess::nullDevice());   // Qt 5.2+
routerProc.setStandardErrorFile(QProcess::nullDevice());
routerProc.start(pathToPhp, args);
```
**Вариант Б (через шелл, если редирект нужен буквально):** запускать `cmd /c "..."`.

## B3
🟠 **`config.ini` сохраняется относительно CWD, а не папки exe** — `MSettings.cpp`.

```cpp
MSettings::MSettings() : QSettings("config.ini", QSettings::IniFormat, 0) {}
```
Относительный путь `"config.ini"` `QSettings` резолвит от **текущего рабочего каталога процесса**. При запуске из ярлыка с заданной «Рабочей папкой» или из другого каталога файл создаётся/читается не рядом с exe — настройки «теряются» или расходятся.

**Исправление.** Передавать абсолютный путь от `applicationDirPath()`:
```cpp
MSettings::MSettings()
    : QSettings(QCoreApplication::applicationDirPath() + "/config.ini",
                QSettings::IniFormat, 0) {}
```

## B4
🟠 **Перевод грузится по стране, а не по языку** — `main.cpp`.

```cpp
if (curent.country() == QLocale::RussianFederation) { ... }
```
Русскоязычные пользователи за пределами РФ (Казахстан, Беларусь и т.д.) получают английский интерфейс, хотя система настроена на русский.

**Исправление.** Проверять язык:
```cpp
if (QLocale().language() == QLocale::Russian) { ... }
```

## B5
🟠 **Гонка: браузер открывается до готовности сервера** — `TrayIcon.cpp`, `startSlot()`.

```cpp
void TrayIcon::startSlot() {
    lunchProcesses();
    openUrl(...);            // сразу, PHP ещё не забиндился
}
```
Первое открытие может упереться в «connection refused», пользователь видит ошибку и обновляет вручную.

**Исправление.** Открывать URL после готовности: дождаться `routerProc.started()` + небольшая задержка, либо опрашивать порт (`QTcpSocket`) до успешного коннекта, затем `openUrl`.

## B6
🟠 **«Монитор» не мониторит процессы** — `TrayIcon` (концептуальный пробел).

Несмотря на название, после запуска код не отслеживает состояние `routerProc`/`taskSchedulerProc`. Если PHP-процесс падает — он не детектируется, не логируется и не перезапускается; пользователь видит «битый» localhost без объяснений.

**Исправление.** Подключить сигналы и реакцию:
```cpp
connect(&routerProc, SIGNAL(finished(int,QProcess::ExitStatus)),
        this, SLOT(onProcessFinished(int,QProcess::ExitStatus)));
```
В слоте — уведомление в трее (`showMessage`) и/или контролируемый перезапуск с защитой от бесконечного цикла рестартов.

## B7
🟡 **`lunchProcesses()` выходит при живом любом из двух процессов** — `TrayIcon.cpp`.

```cpp
if (routerProc.state() != QProcess::NotRunning
        || taskSchedulerProc.state() != QProcess::NotRunning)
    return;
```
Если один процесс упал, а второй жив, повторный запуск не поднимет упавший. Связано с [B6](#b6).

**Исправление.** Проверять и запускать каждый процесс независимо.

## B8
🟡 **Нет GPLv3-заголовков в исходниках** — все `.cpp`/`.h`.

Файл `LICENSE` (GPLv3) есть, но ни в одном исходнике нет шапки с копирайтом и ссылкой на лицензию. Это нарушает требование проекта (см. границы в корневом [CLAUDE.md](../CLAUDE.md)) и рекомендации FSF.

**Исправление.** Добавить стандартную GPLv3-шапку в начало каждого `.cpp`/`.h` (копирайт, год, ссылка на лицензию).

## B9
🟡 **Мёртвое объявление `isPathChanged()`** — `TrayIcon.h`.

```cpp
bool isPathChanged();
```
Метод объявлен, но нигде не определён и не вызывается (логика «сменилась ли папка» реализована инлайн в конструкторе через сравнение `lastAppPath`).

**Исправление.** Либо удалить объявление, либо вынести инлайн-логику в этот метод и использовать его.

---

## B10
🟡 **`restartSlot()` не переоткрывает URL** — `TrayIcon.cpp`.

`startSlot()` открывает браузер, а `restartSlot()` запускает только `lunchProcesses()` (через таймер) и URL не открывает. Поведение «Старт» и «Перезапуск» несогласованно.

**Исправление.** Привести к единому поведению — после перезапуска тоже открывать (или осознанно не открывать в обоих случаях).

---

## B11
🟡 **Значения настроек не экранируются в командной строке** — `TrayIcon.cpp`.

`pathToPhp`, `addr`, `port` подставляются в строку команды, которую `QProcess::start(QString)` разбивает по пробелам. Пробел или спецсимвол в этих значениях (берутся из `config.ini`) ломает разбор и допускает инъекцию аргументов. `appDirPath` валидируется регуляркой, а эти значения — нет.

**Исправление.** Перейти на `start(program, QStringList args)` ([B2](#b2)) — тогда экранирование делает Qt.

---

## B12
🟡 **Гигиена репозитория** — `anime_monitor.pro.user`, отсутствие `.gitignore`.

Закоммичено состояние Qt Creator (`*.pro.user`) — это локальные пути и настройки IDE конкретного разработчика, им не место в VCS. `.gitignore` отсутствует, поэтому артефакты сборки (`Makefile`, `*.o`, `release/`, `debug/`, `moc_*`, `*.qm` при желании) легко попадут в коммиты.

**Исправление.** Удалить `*.pro.user` из индекса и добавить `.gitignore` (см. [RECOMMENDATIONS.md](RECOMMENDATIONS.md)).

---

## B13
⚪ **Синглтон `MSettings` не освобождается** — `MSettings.cpp`.

`ptr = new MSettings()` никогда не удаляется. Утечка на время жизни процесса, практически безвредна для трей-утилиты, но формально — leak. Можно оставить как есть или обнулять при выходе.
